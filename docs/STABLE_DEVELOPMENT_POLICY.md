# AssetForge Studio — Stable Development Policy

## Назначение

Этот документ фиксирует правила разработки через ZIP-архивы до подключения
полноценного Git-репозитория.

## Основной принцип

Рабочий код не изменяется без подтверждённой необходимости.

Новые возможности создаются как отдельные модули и подключаются к приложению
через минимальные точки интеграции.

## Замороженные компоненты

Следующие компоненты считаются `Frozen Core`:

- `app/blender_runner.py`
- `app/unity_runner.py`
- `app/unity_asset_library.py`
- `app/settings_store.py`
- `core/project/`
- `core/events/`
- `core/jobs/`
- `core/database/`
- `core/plugins/`
- проверенные Blender workers
- существующие форматы manifest/report

Изменение Frozen Core допускается только для:

1. подтверждённой ошибки;
2. проблемы безопасности;
3. несовместимости с реальной версией Blender, Unity или Python;
4. обязательной миграции данных.

Каждое такое изменение должно оформляться отдельным Hotfix-релизом.

## Stable и Dev

### Stable

- используется как рабочая версия;
- содержит только проверенные функции;
- не получает экспериментальные возможности;
- всегда публикуется отдельным ZIP;
- содержит SHA-256 manifest и результаты тестов.

### Dev

- создаётся только из последней Stable;
- может содержать новые модули;
- не заменяет Stable;
- после подтверждённого тестирования становится новой Stable.

## Правила версий

- `v0.8.1 Stable` — стабильная рабочая точка;
- `v0.8.2 Dev` — новая функция в разработке;
- `v0.8.2 Stable` — функция проверена и принята;
- `v0.8.2.1 Hotfix` — исправление подтверждённой ошибки.

## Обязательная комплектация ZIP

Каждый стабильный архив содержит:

- исходный код;
- `README.md`;
- `CHANGELOG.md`;
- `BUILD_REPORT*.json`;
- `TEST_RESULTS*.txt`;
- `MANIFEST.sha256`;
- release notes;
- список известных ограничений.

## Запреты

- не переписывать GUI целиком ради одной функции;
- не менять форматы существующих manifest без миграции;
- не объединять несколько крупных новых функций в один релиз;
- не удалять рабочий код до появления проверенной замены;
- не называть сборку Stable без автоматических тестов и проверки запуска пользователем.
