# ZIP Release Workflow

## 1. Исходная точка

Всегда использовать последний архив с маркировкой `STABLE_BASELINE` или `Stable`.

## 2. Разработка

Новая функция получает:

- отдельный модуль;
- отдельные тесты;
- отдельную документацию;
- минимальную интеграцию с GUI.

## 3. Проверка

Обязательные проверки:

```text
python -m compileall -q app core worker tests
python -m unittest discover -s tests -v
python run.py
```

Последняя команда выполняется пользователем на целевой Windows-машине.

## 4. Решение

- запуск и функция подтверждены → новая Stable;
- запуск работает, функция не подтверждена → Preview;
- запуск сломан → возврат к предыдущей Stable;
- ошибка в Stable → отдельный Hotfix.

## 5. Хранение

Рекомендуется локально хранить не менее трёх архивов:

- последняя Stable;
- предыдущая Stable;
- текущая Dev.
